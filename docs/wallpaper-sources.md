# 壁纸源实测报告

> 2026-11-12 真实发请求测出来的，不是查资料。所有尺寸都是从图片字节流里解出来的实际像素，不是接口自称。

## 结论

```
用途            选谁              原因
──────────────────────────────────────────────────────────────────
默认每日壁纸    Bing 每日 UHD     ✅ 免 key、7 天历史全是真 4K、500ms、带中文标题
「换一张」      Wallhaven API     ✅ 免 key、池子 9.6 万张、45 次/分钟够用
占位/兜底       纯色渐变          不依赖网络，永不失败
```

排除的：

```
源                  实测结果        结论
──────────────────────────────────────────────────────────────
Unsplash 官方 API   401 无 key      必须注册 key，不做默认依赖
source.unsplash     503             服务已下线，别再写进方案
NASA APOD           500             拿 DEMO_KEY 直接报错，不可靠
Picsum              200/可出 4K     图是随机风景，0.52MB 强压缩画质差，耗时 3.2s
                                    只能当占位图，不能当「精选壁纸」
```

## Bing 每日 UHD（主源）

```
接口      https://www.bing.com/HPImageArchive.aspx?format=js&idx=0&n=1&mkt=zh-CN
UHD 变体  把返回 url 里的 _1920x1080 替换成 _UHD
```

实测最近 8 天（全部 3840×2160 真 4K）：

```
idx  日期        状态  实际尺寸     体积      标题
────────────────────────────────────────────────────────────
 0   2026-11-11  200   3840x2160   3.54MB   没有建筑师的建筑杰作
 1   2026-11-10  200   3840x2160   3.35MB   奇妙纷呈的森林
 2   2026-11-09  200   3840x2160   3.39MB   惬意放松，尽享海岛时光
 3   2026-11-08  200   3840x2160   3.49MB   艺术与韵律交汇之地
 4   2026-11-07  200   3840x2160   3.50MB   光芒四射的节日
 5   2026-11-06  200   3840x2160   3.58MB   归来的草原巨兽
 6   2026-11-05  200   3840x2160   3.53MB   穿越毛伊岛的绿色隧道
 7   2026-11-04  200   3840x2160   3.58MB   向山巅再迈一步
```

⚠️ 同一个 URL 加 `&w=3840&h=2160` 也能拿 4K，但只有 **0.80MB**（强压缩，画质明显降）。
要画质就用 `_UHD` 后缀那版（3.5MB）。

其他实测：1080 版 0.32MB / 286ms；UHD 版 494ms。接口本身 177ms。

## Wallhaven（换一张）

```
接口  https://wallhaven.cc/api/v1/search?categories=100&purity=100&sorting=toplist&ratios=16x9&atleast=3840x2160
限流  45 次/分钟（匿名，实测连打 3 次 40→39→38）
```

池子大小（实测）：

```
查询条件                      总数       首条实际分辨率
──────────────────────────────────────────────────────
toplist + 16:9 + ≥4K          337       3840x2160
全分类 random + ≥4K           96434      6240x4160   ← 池子最大，但尺寸超纲
关键词 nature + ≥4K           120        7008x4672
```

⚠️ **必须做尺寸收敛**：全分类随机会抽到 6240×4160 这种超纲图，直接当壁纸会拖慢首屏。
拉下来后统一缩到屏幕 2 倍宽（如 3840）+ 重编码，不能原样存。

## Picsum（仅占位）

```
https://picsum.photos/3840/2160  →  200 / 3840x2160 / 0.52MB / 3210ms
```

尺寸对，但 4K 只有 0.52MB 说明压缩很狠；随机抽图不讲构图；耗时 3.2 秒是最慢的一个。
只在「壁纸加载失败」时当兜底背景色用，不单独作为壁纸源。

## 缓存与清理（按实测体积定参数）

真实单张 3.4-3.6MB，据此：

```
单张上限        15MB      超了直接拒绝，不下载（Wallhaven 超纲图靠这条挡）
总容量上限      300MB     约等于 85 张
每日策略        同一天只留一张，新的一天覆盖旧的
保留窗口        最近 30 天  ≈ 105MB，留点余量给自定义上传
清理顺序        先删超出保留窗口的 → 再按最久未访问删到容量上限以下
自定义上传      10MB 内，jpg/png/webp；超过 4K 自动压缩后入库
缩略缓存        按屏幕宽度生成 webp，原图保留
失败处理        静默回退默认底，绝不阻塞首屏等壁纸
```

## 版权与仓库纪律 🔴

```
Bing 每日壁纸     图源为 Getty / 摄影师投稿，个人自用没问题
Wallhaven        用户上传，许可各异
⇒ 两条红线：
  ① 下载的壁纸只存本地缓存目录，【绝不进入 git 仓库】
  ② 仓库里的 .gitignore 必须包含壁纸缓存目录，且验证忽略生效
     （cd 项目 && git status --short --ignored，命中的行必须以 !! 开头）
```

这条不是形式主义：本项目要公开到 GitHub，一次误提交就是替别人分发版权图片。

## 抓取时机

```
每天一次       定时任务，取 idx=0，落盘后按保留窗口清理
换一张         用户点按钮时按需拉 1 次（45 次/分钟限流完全够）
不与首屏耦合   页面渲染不等壁纸；先出内容，壁纸异步换上并淡入
```
